# 中国电信知识库与智能客服 DEMO 详细开发说明书

> 文档版本：V1.0  
> 项目性质：演示验证（DEMO/POC）  
> 建议场景：中国电信某新区分公司面向园区政企客户的云网融合服务  
> 数据声明：全部客户、人员、号码、业务量、工单和经营指标均为模拟或脱敏数据，不代表真实生产经营情况。界面应固定显示“演示环境｜模拟数据”。

## 1. 文档目的

本文用于指导产品、UI、前端、后端、AI、测试及演示人员完成“企业知识中枢”和“智能客服运营中心”两套相互联动的 DEMO。

系统以企业知识库为能力底座，以智能客服为业务入口，以检修工单为主闭环，并扩展智能 BI、供应商知识和工业场景，形成可展示、可操作、可追溯、可解释的完整演示系统。

## 2. 需求来源与融合原则

### 2.1 原 Markdown 核心要求

- 支持文本、图片等多模态知识导入与检索。
- 客服回答展示答案、置信度、引用来源及是否触发人工工单。
- 问答效果不佳或超出知识范围时，自动创建人工工单。
- 工单通过邮件通知指定专员，专员回复后将结果转交用户。
- 展示邮件 ID、收件人、发送时间、发送状态及重试过程。
- 页面可查看工作流日志、工单状态和消息收发状态。
- 测试应覆盖准确性、置信度判断、边缘问题、邮件异常及闭环流程。

### 2.2 参考图片融合内容

- 客服全流程：诉求上报、受理、分流、派发、办理、回访、运营、质检和培训。
- 企业知识库：设备、产品、生产工艺、安全生产、制度流程、售前售后等知识问答。
- 智能 BI：用自然语言查询业务、生成分析结论和图表。
- 工业场景：研发设计、生产制造、采购供应链、销售服务和运营管理。
- 供应商生命周期：客服、引入、认证、推荐、投标、评标、中标和评价。
- 产品能力：知识库、ChatBI、任务式对话、对话分析和对话控制。

## 7. 核心业务流程

### 7.1 智能问答流程

1. 用户输入文本，并可上传故障截图、设备照片或资费图片。
2. 系统执行敏感信息检测、问题分类、实体抽取和上下文补全。
3. 根据意图选择知识空间和检索策略。
4. 同时进行关键词检索、向量检索和图片语义检索。
5. 对候选片段重排，生成带引用答案。
6. 计算综合置信度。
7. 高置信度直接回复；中置信度追问澄清；低置信度或高风险问题转人工。
8. 保存问答、引用、模型版本、延迟和用户反馈。

综合置信度建议：

```text
confidence = 0.35 × 检索相关度
           + 0.25 × 重排得分
           + 0.20 × 答案引用覆盖度
           + 0.10 × 意图识别置信度
           + 0.10 × 规则校验得分
```

阈值建议：

- `confidence >= 0.78`：直接回答。
- `0.55 <= confidence < 0.78`：回答并提示需核实，或发起澄清问题。
- `confidence < 0.55`：创建人工工单。
- 涉及资费承诺、赔付、安全生产、重大故障等高风险意图，无论分数高低均可强制复核。

### 7.2 检修主流程

```text
客户报障
→ 客户及产品实例识别
→ 文本/图片故障信息抽取
→ 模拟网管诊断
→ 检索处理规程与相似案例
→ AI给出初判及自助建议
→ 未解决/低置信度/高风险
→ 自动生成检修工单
→ 派发检修专员并发送邮件/站内通知
→ 专员邮件或工作台回复
→ 解析回复并回写工单
→ 客服向客户反馈
→ 客户确认
→ 回访、质检、知识沉淀
```

主场景固定为“新区智造科技有限公司互联网专线丢包”。预置诊断结果：

- 电路编号：XZ-IP-20260918-0176。
- 接入设备：XZ-OLT-03。
- 端口状态：在线。
- 接收光功率：-25.8 dBm。
- 近 30 分钟丢包率：18.6%。
- 同区域关联告警：3 条。
- AI 初判：园区汇聚链路光衰异常，建议派发网络维护中心复测。
- 自动工单：XZ202609240087，优先级 P1，SLA 4 小时。

### 7.3 人工审核与邮件闭环

1. 工作流生成工单及邮件正文。
2. 邮件适配器向目标专员发送通知。
3. 记录邮件 ID、收件人、发送时间、状态、错误码和重试次数。
4. 专员通过邮件回复，主题或邮件头携带工单号。
5. 接收服务解析邮件正文、附件和引用内容。
6. 系统将回复绑定工单并更新为“专员已回复”。
7. AI 将专业回复整理为客户可读话术。
8. 客服确认后一键转交用户；演示模式也可自动转交。
9. 用户确认解决后关闭工单；未解决则重新打开并升级。

异常策略：

- SMTP 失败后按 1、3、10 分钟重试三次。
- 三次失败后转站内消息，并在工作流中标红。
- 无法解析回复时进入“待人工归档”。
- 超过 SLA 未回复时升级至值班主管。

### 7.4 知识运营闭环

未命中问题或人工解决方案自动形成候选知识，包括问题、标准答案、来源工单、适用产品、有效期和敏感级别。知识运营员审核、修改并发布后，重新建立索引；新知识在下一次相似问答中参与检索。

## 8. 企业知识中枢详细需求

### 8.1 知识总览页

展示指标：知识库数、文档数、知识片段数、本月新增、知识覆盖率、问答命中率、引用溯源率、待审核数。

展示图表：文档类型分布、知识更新趋势、热门知识 TOP10、低质量知识、部门贡献排行、未命中问题聚类。

### 8.2 知识空间

预置空间：

- 云网产品知识库。
- 政企业务知识库。
- 网络运维与检修知识库。
- 客户服务规范库。
- 故障案例与应急预案库。
- 新区园区行业解决方案库。
- 工业知识库。
- 供应商管理知识库。

工业知识按参考内容细分为设备、产品、生产工艺、安全生产、制度流程、售前售后。

### 8.3 文档管理

支持 PDF、DOCX、XLSX、PPTX、TXT、Markdown、HTML、JPG、PNG。字段包括文档名称、编号、版本、来源部门、生效日期、失效日期、密级、标签、知识空间、解析状态、审核状态及调用次数。

入库流程：上传 → 病毒/格式检查 → OCR/版面解析 → 分段 → 元数据抽取 → 向量化 → 质量检查 → 审核 → 发布。

必须保留页码、标题层级、表格位置及图片与正文的关联，确保答案可定位原文。

### 8.4 多模态知识

- 图片入库时生成 OCR 文本、图片说明、对象标签和向量。
- 用户上传设备告警截图时，识别错误码、告警灯、设备型号和关键数值。
- 图片检索结果需同时展示缩略图、来源文档、页码和相关文字片段。
- 不确定识别结果需标注“图片识别结果待确认”。

### 8.5 智能问答页

页面由会话区、答案区、引用证据区和调试信息抽屉组成。答案必须支持：

- 流式输出。
- Markdown、表格和步骤。
- 置信度等级和数值。
- 引用角标及原文定位。
- 相关问题推荐。
- 点赞、点踩和问题反馈。
- 一键转人工、一键建单、一键生成客户话术。
- 调试模式查看召回片段、得分、耗时和模型版本。

### 8.6 知识图谱

DEMO 使用轻量关系图即可，实体包括客户、行业、需求、产品、方案、设备、故障、工单、供应商和制度。点击实体显示关联知识及统计，不要求建设完整图数据库。

## 9. 智能客服详细需求

### 9.1 客服总览

展示排队人数、今日会话量、机器人解决率、转人工率、平均响应时间、一次解决率、满意度和高风险会话。

### 9.2 客服工作台

左栏为会话队列，中栏为对话，右栏为 AI 助手。

右栏模块包括：

- 客户 360°画像。
- 意图与情绪识别。
- 产品实例及 SLA。
- 推荐话术。
- 推荐知识及引用。
- 相似历史工单。
- 风险提示。
- 下一步操作。
- 会话摘要与工单草稿。

坐席可采用、编辑或拒绝 AI 建议；系统记录采纳情况用于运营分析。

### 9.3 会话控制

支持机器人接待、转人工、人工接管、退回机器人、邀请专家、结束会话及会话转派。状态包含排队中、机器人处理中、待人工、人工处理中、待客户、已结束和异常。

### 9.4 渠道

DEMO 展示网页、微信服务号、企业微信、小程序和语音转写入口。除网页外可使用模拟渠道，但消息模型必须统一。

### 9.5 智能派单

派单综合考虑业务类型、客户等级、区域、产品、技能组、值班状态和当前负载。派单结果需显示“推荐原因”和可人工调整。

## 10. 检修工单中心

### 10.1 工单状态机

```text
草稿 → 待派发 → 待受理 → 处理中 → 待客户确认 → 已关闭
                    ├→ 待补充信息
                    ├→ 已升级
                    └→ 已退回
任意处理中状态 → 已取消（需原因）
已关闭 → 重新打开
```

### 10.2 工单字段

- 工单号、来源会话、来源渠道。
- 客户、联系人、联系电话（脱敏）。
- 产品、产品实例、电路编号。
- 故障现象、发生时间、影响范围。
- 图片附件、诊断结果和相关告警。
- AI 初判、引用知识和相似案例。
- 优先级、SLA、责任部门、处理人。
- 根因、解决方案、现场记录。
- 创建、受理、到场、恢复、关闭时间。
- 客户确认、评价、回访结果。

### 10.3 SLA

P1、P2、P3、P4 分别配置响应和解决时限。页面显示倒计时；达到 70%、90%、100% 时分别预警、升级和超时。暂停 SLA 必须填写原因并记录审批人。

### 10.4 时间轴

统一展示用户消息、AI 判断、坐席操作、派单、邮件、专员回复、状态变化、附件和回访，作为演示可信度的核心页面。

## 11. 邮件与消息中心

### 11.1 邮件记录页

字段：邮件 ID、关联工单、方向、发件人、收件人、主题、发送时间、接收时间、状态、重试次数、失败原因、附件数。

状态：待发送、发送中、发送成功、投递失败、已接收、解析成功、解析失败、已重试、已降级。

### 11.2 工作流日志

每次执行生成 Trace ID，展示节点名称、输入摘要、输出摘要、开始时间、耗时、状态和错误详情。敏感信息默认脱敏，管理员可查看审计后的完整数据。

## 12. 智能质检、回访与培训

### 12.1 质检规则

- 身份核验。
- 标准问候和结束语。
- 诉求识别完整性。
- 工单号告知。
- 禁语与不当承诺。
- 情绪安抚。
- 隐私泄露。
- 摘要准确性。
- SLA 告知准确性。
- 解决方案是否引用有效知识。

每条规则显示证据句、发生时间、扣分、严重程度和整改建议。

### 12.2 智能回访

工单关闭后模拟发送回访消息，采集是否解决、处理速度、服务态度、总体满意度及补充意见。负面回访自动生成二次跟进任务。

### 12.3 智能培训

根据质检薄弱项生成坐席训练题，内容包括产品知识、服务规范、典型故障和模拟对话。作为扩展页展示即可。

## 13. 运营驾驶舱与 ChatBI

### 13.1 看板指标

预置：今日接待 3,286、机器人解决率 71.4%、转人工率 28.6%、平均响应 1.8 秒、平均人工处理 6 分 24 秒、一次解决率 88.9%、工单按时办结率 96.7%、满意度 94.2%、知识推荐采纳率 82.5%。

图表包括服务量趋势、渠道分布、热点诉求、情绪趋势、工单区域分布、产品故障占比、SLA 预警和坐席绩效。

### 13.2 ChatBI

支持自然语言提问：

- “本周专线故障最多的三个园区是什么？”
- “对比近 7 天与前 7 天机器人解决率。”
- “哪些产品的重复报障率最高？”
- “列出即将超时的 P1 工单并按剩余时间排序。”
- “分析供应商未中标的主要原因。”

回答包含口径说明、结果表格、图表、洞察摘要和 SQL/数据来源抽屉。DEMO 可采用白名单查询模板，不允许模型直接执行任意 SQL。

## 14. 供应商管理扩展

依据参考图设计八阶段：客服、引入、认证、推荐、投标、评标、中标、评价。

本期重点展示：供应商知识问答、项目与供应商智能匹配、投标建议生成、未中标原因分析和 360°画像。供应商数据均为虚构，不与真实采购活动产生关联。

## 16. API 设计

### 16.1 知识接口

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/knowledge/documents` | 上传文档 |
| GET | `/knowledge/documents` | 查询文档 |
| GET | `/knowledge/documents/{id}` | 文档详情与解析状态 |
| POST | `/knowledge/documents/{id}/publish` | 发布知识 |
| POST | `/knowledge/search` | 多模态检索 |
| POST | `/knowledge/ask` | 知识问答 |


## 18. UI 与视觉规范

- 主色采用电信蓝，辅色为科技青；红色用于重大告警，橙色用于预警，绿色用于成功。
- 避免照搬真实生产系统；使用获授权的品牌资源和自有组件。
- 页面尺寸优先适配 1920×1080 和 1440×900。
- 表格、流程状态、时间轴和图表统一组件风格。
- 所有详情页保留面包屑、更新时间、数据来源和状态。
- 页面右上或页脚固定显示“演示环境｜模拟数据”。
- 数值变化、加载、工作流执行使用适度动效，单步时长 300～800ms。
- 重要错误必须有可理解的错误原因及恢复按钮，不能只弹“系统异常”。

## 20. 非功能要求

### 20.1 性能

- 普通页面首屏小于 2 秒。
- 文本问答首 token 小于 3 秒，完整答案小于 10 秒。
- 普通检索 P95 小于 1.5 秒。
- 工单创建小于 2 秒。
- 工作流状态每 1 秒内通过 SSE/WebSocket 或轮询更新。

### 20.2 稳定性

- 模型、邮件、网管模拟服务均需超时、重试和降级。
- 断网模式下主演示路径可由 Mock 数据完成。
- 每个关键操作可重复执行并避免重复建单、重复发信。

### 20.3 安全与审计

- 所有敏感字段脱敏。
- 文件上传限制类型和大小。
- 模型提示词防注入；用户上传文档内容仅作为数据，不作为系统指令执行。
- 工单、邮件、知识发布和权限变化写入审计日志。
- 不在日志中记录邮箱密码、授权码、模型密钥和完整个人信息。

## 22. 演示脚本

### 22.1 主脚本（12～15 分钟）

1. 首页介绍统一平台及今日运营指标。
2. 进入知识中枢，展示文档、图片、知识解析和引用溯源。
3. 客户上传专线告警截图并描述“从上午 9 点开始频繁丢包”。
4. 系统识别客户、电路、告警信息并调用模拟网管诊断。
5. AI 检索规程和历史案例，输出初判及处理步骤。
6. 因丢包率高且属于金牌客户，系统自动创建 P1 检修工单。
7. 展示邮件通知、工作流节点和 Trace ID。
8. 切换检修专员角色，通过邮件模拟回复“已处理汇聚链路光衰”。
9. 工单自动回写，客服获得面向客户的回复话术。
10. 客户确认恢复，完成回访和智能质检。
11. 进入驾驶舱，用 ChatBI 查询本周专线故障最多的园区。
12. 展示人工解决方案进入候选知识并审核发布。

### 22.2 备用脚本

- 云主机在线扩容咨询：高置信度回答，不建单。
- 重复投诉：情绪升级、转人工、带入历史工单。
- 未识别设备告警图片：追问设备型号并转专家审核。
- 邮件服务故障：展示重试和站内消息降级。

## 25. 开发完成定义（DoD）

满足以下条件方可认为 DEMO 完成：

1. 主演示脚本从头到尾可连续操作，无需修改数据库或手工补状态。
2. 文本和图片知识均能导入、检索并展示引用。
3. 三档置信度策略均有可复现用例。
4. 低置信度/高风险问题可自动进入检修工单。
5. 邮件通知、专员回复、用户反馈的状态完整可见。
6. 工单时间轴和工作流日志可追溯。
7. 质检、回访、驾驶舱和 ChatBI 使用同一批一致数据。
8. 模型或外部服务异常时有明确降级路径。
9. 所有页面明确标记演示环境和模拟数据。
10. 演示机器断网时仍能完成主流程。
