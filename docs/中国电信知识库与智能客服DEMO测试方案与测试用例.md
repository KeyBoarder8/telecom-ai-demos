# 中国电信知识库与智能客服 DEMO 测试方案与测试用例

> 版本：V1.0  
> 对应需求：《中国电信知识库与智能客服 DEMO 详细开发说明书》V1.0  
> 测试数据：全部为模拟或脱敏数据

## 1. 测试目标

验证以下关键能力可用、稳定且可追溯：

- 文本、表格、图片等多模态知识正确入库和检索。
- RAG 回答准确、引用真实、页码可定位，不无依据编造。
- 高、中、低三档置信度能够正确分流。
- 客服会话、模拟诊断、检修工单和 SLA 状态流转正确。
- 邮件通知、专员回复、用户转交及异常重试形成闭环。
- 工作流节点、Trace ID、邮件和工单时间轴完整对应。
- 质检、回访、驾驶舱与 ChatBI 数据口径一致。
- 权限、脱敏、提示词注入防护及审计满足 DEMO 要求。
- 主流程在外部模型或邮件服务不可用时可以降级演示。

## 2. 测试范围

### 2.1 纳入范围

统一门户、知识空间、文档导入、多模态解析、智能问答、客服工作台、模拟网管诊断、检修工单、邮件中心、工作流日志、智能质检、回访、运营驾驶舱、ChatBI、供应商助手、权限与审计。

### 2.2 不纳入范围

真实 10000 号、CRM、综合网管、真实邮件生产环境、真实网络指令下发、真实采购与资费办理。

## 3. 测试策略

| 测试类型 | 目标 | 执行方式 |
|---|---|---|
| 冒烟测试 | 保证主演示路径可运行 | 每次部署后自动/人工执行 |
| 功能测试 | 验证页面、接口和状态机 | API + UI |
| AI 效果测试 | 验证检索、答案、引用和置信度 | 固定评测集 + 人工复核 |
| 多模态测试 | 验证 OCR、图片理解和图文检索 | 标准图片集 |
| 集成测试 | 验证客服、工单、邮件、工作流联动 | 端到端 |
| 异常测试 | 验证超时、失败、重试和降级 | Mock 故障注入 |
| 安全测试 | 验证权限、脱敏、注入与审计 | 角色矩阵 + 攻击样例 |
| 性能测试 | 验证响应时间和并发稳定性 | k6/JMeter 或脚本 |
| 兼容性测试 | 验证演示机器和分辨率 | Chrome/Edge、两种分辨率 |

## 9. AI 效果判定标准

### 9.1 答案评分

每题按 10 分计：事实正确 4 分、关键步骤完整 2 分、引用正确 2 分、表达与边界 1 分、风险控制 1 分。低于 7 分判定失败。

### 9.2 引用评分

引用必须同时满足：文档真实存在、版本有效、页码正确、原文支持结论。任一不满足即判定该条引用失败；答案包含关键事实但无引用时同样失败。

### 9.3 分流混淆矩阵

统计应转人工/不应转人工的 TP、FP、FN、TN，并计算：

- 转人工准确率 `TP / (TP + FP)`。
- 转人工召回率 `TP / (TP + FN)`。
- 高风险问题漏转人工数量必须为 0。

## 10. 缺陷分级

| 等级 | 定义 | 示例 |
|---|---|---|
| 阻断 | 主流程无法继续且无规避方案 | 无法登录、无法问答、无法建单 |
| 严重 | 核心结果错误或存在安全风险 | 引用虚假、客户数据越权、重复发信 |
| 一般 | 局部功能异常，有规避方案 | 筛选错误、次要状态延迟 |
| 建议 | 不影响功能的体验问题 | 文案、间距、非关键动效 |
